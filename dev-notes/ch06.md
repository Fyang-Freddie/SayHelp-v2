# ch06 — Task 4：真实嵌入与精排（FlagEmbedding API 核实记录）

> 红线要求：不按记忆照抄，`BGEM3FlagModel` / `FlagReranker` 的确切构造参数与返回值结构
> 必须用官方来源核实后记录于此。以下均来自 FlagEmbedding v1.4.2（当前 PyPI 最新版）的
> 官方 GitHub 源码，逐条给出源 URL。

## 核实方法

- 主 README（`https://github.com/FlagOpen/FlagEmbedding`）已不再内嵌完整 API 示例，
  只列出模型名（BGE-M3、bge-reranker-v2-m3 等），故改用仓库 tag `v1.4.2` 的源码文件核实。
- 版本确认：PyPI `FlagEmbedding` 最新版为 1.4.2；`requirements.txt` 锁定 `FlagEmbedding>=1.3`
  会解析到 1.4.x。`v1.4.2` 的 `FlagEmbedding/inference/__init__.py` 仍导出
  `BGEM3FlagModel` 与 `FlagReranker` 两个名字（向后兼容别名）。

## 1. BGEM3FlagModel（BGE-M3 嵌入）

- 源：`https://raw.githubusercontent.com/FlagOpen/FlagEmbedding/v1.4.2/FlagEmbedding/inference/embedder/encoder_only/m3.py`
- 导出别名：`FlagEmbedding/inference/embedder/encoder_only/__init__.py` 中
  `from .m3 import M3Embedder as BGEM3FlagModel`。
- 构造签名（节选）：
  ```python
  def __init__(
      self,
      model_name_or_path: str,
      normalize_embeddings: bool = True,
      use_fp16: bool = True,
      ...
      return_dense: bool = True,
      return_sparse: bool = False,
      return_colbert_vecs: bool = False,
      truncate_dim: Optional[int] = None,
      **kwargs: Any,
  ):
  ```
  注意：第一个参数名是 `model_name_or_path`（不是 `model_name`）。我们封装层
  `BGEM3Embedder(model_name=...)` 把 `self.model_name` 作为第一个**位置参数**传入，
  因此参数名差异不影响使用。
- `encode()` 返回类型（m3.py 内 `encode` 的 docstring 原样）：
  ```
  Dict[Literal["dense_vecs", "lexical_weights", "colbert_vecs"],
       Union[np.ndarray, List[Dict[str, float]], List[np.ndarray]]]
  ```
  → 稠密向量取 `out["dense_vecs"]`（`numpy.ndarray`，shape `(n, dim)`），
  封装层用 `.tolist()` 转为 `list[list[float]]`。

### 稠密维度 = 1024 的独立佐证

- BGE-M3 模型配置（HuggingFace 官方模型卡配置文件）：
  `https://huggingface.co/BAAI/bge-m3/resolve/main/config.json`
  实测字段 `hidden_size = 1024`（`model_type = xlm-roberta`），即 dense_vecs 维度 1024。

## 2. FlagReranker（bge-reranker-v2-m3 精排）

- 源：`https://raw.githubusercontent.com/FlagOpen/FlagEmbedding/v1.4.2/FlagEmbedding/inference/reranker/encoder_only/base.py`
  （`FlagReranker` 是 `BaseReranker` 的别名，见
  `FlagEmbedding/inference/reranker/encoder_only/__init__.py` 及相关导出）
- 构造签名（节选）：
  ```python
  def __init__(
      self,
      model_name_or_path: str,
      use_fp16: bool = False,
      ...
      normalize: bool = False,
      **kwargs: Any,
  ):
  ```
- `compute_score`（定义于 `abc/inference/AbsReranker.py`，节选签名与行为）：
  ```python
  def compute_score(
      self,
      sentence_pairs: Union[List[Tuple[str, str]], Tuple[str, str]],
      **kwargs
  ):
  ```
  - 入参形状：**句对列表**，即 `[[query, passage], [query2, passage2], ...]`。
    若传单个 `(query, passage)` 元组（`sentence_pairs[0]` 为 str），内部自动包成单元素列表。
  - 返回类型：`List[float]`（单设备路径 `compute_score_single_gpu` 用
    `scores.cpu().numpy().tolist()` 返回 `List[float]`；`normalize=True` 时经 sigmoid）。

## 实现映射（app/rag/bge.py）

| 协议/类 | 底层调用 |
|---|---|
| `BGEM3Embedder.encode_dense(texts)` | `BGEM3FlagModel(self.model_name, use_fp16=...).encode(texts, return_dense=True, return_sparse=False, return_colbert_vecs=False)["dense_vecs"].tolist()` |
| `BGEReranker.rerank(query, passages)` | `FlagReranker(self.model_name).compute_score([[query, p] for p in passages])` |

- `embedding_use_fp16` 来自 `app.config.settings`（默认 `False`），在**首次调用时**才读取。
- 两类的 `__init__` 只存 `model_name` 并置 `model = None`，不 import FlagEmbedding/torch，
  不触发任何下载 —— 保证测试 `dim == 1024`、`model is None` 在未安装依赖时也能通过。

## Python 3.13 兼容性备注

- 本机解释器为 Python 3.13.9，torch / FlagEmbedding 均未安装（本任务明确不安装、不下载模型）。
- FlagEmbedding 依赖 torch；torch 自 2.6 起提供 cp313 wheel。此处未实际安装验证，
  若安装 `FlagEmbedding>=1.3` 时 torch/transformers 装不上，按任务约定停下报告，
  由负责人裁定降级方案（onnxruntime BGE-M3 或 sentence-transformers），不擅自换模型。

# Task 5：pymilvus / Milvus（collection + BM25 hybrid search + RRF）核实记录

> 红线要求：不按记忆照抄 `Function` / `AnnSearchRequest` / `hybrid_search` / `RRFRanker` 的
> 确切参数名与调用序，必须核实后记录于此。核实手段：① 直接对**实际安装的**
> `pymilvus 3.0.2` / `milvus-lite 3.2.2` 用 `inspect.signature` 读出签名（运行时真值）；
> ② milvus.io 官方文档（2.5.x / 默认版）；③ milvus-lite 用临时 db 目录做端到端实测。

## 版本事实（重要）

`requirements.txt` 按任务要求写 `pymilvus>=2.5`、`milvus-lite>=2.5`，**无上界**，
pip 实际解析到：

- `pymilvus==3.0.2`（`>=2.5` 今天不再装到 2.5.x）
- `milvus-lite==3.2.2`
- 附带 `grpcio 1.84.0`、`faiss-cpu 1.15.1`（均有 cp313-win wheel，Python 3.13.9 装得上）

因此“pymilvus 2.5 文档”里的 ORM 写法在 3.0.2 仍可用（ORM API 在 3.1 才移除），
本任务用的是 3.0.2 实测的 ORM 签名。

## 1. 确切 API 签名（来源：`inspect.signature`，安装的 pymilvus 3.0.2）

```python
# ORM 风格（本任务所用；与 brief 的 rerank= 一致）
Collection.hybrid_search(self, reqs: List, rerank: BaseRanker, limit: int,
    partition_names=None, output_fields=None, timeout=None, round_decimal=-1,
    ranker=None, **kwargs)      # -> 注意：ORM 用 reqs= / rerank=（不是 ranker=）
AnnSearchRequest.__init__(self, data, anns_field: str, param: Dict, limit: int,
    expr=None, expr_params=None, filter=None)
RRFRanker.__init__(self, k: int = 60)
Function.__init__(self, name, function_type, input_field_names,
    output_field_names=None, description='', params=None)
# MilvusClient 风格（对比；本任务不用）
MilvusClient.hybrid_search(self, collection_name, reqs, ranker, limit=10, ...)
    # 注意：MilvusClient 用 ranker=，ORM Collection 用 rerank= —— 两个 API 参数名不同
```

- `FunctionType.BM25` 存在；`DataType.SPARSE_FLOAT_VECTOR = 104`。
- 官方文档佐证（MilvusClient 侧 `reqs=`/`ranker=`）：
  `https://milvus.io/docs/multi-vector-search.md`（multi-vector hybrid search 示例，
  `AnnSearchRequest(**{"data","anns_field","param","limit"})`、`RRFRanker(k)`）。

## 2. Schema / BM25 Function（来源：milvus.io + 实测）

- `https://milvus.io/docs/v2.5.x/full-text-search.md` 的示例确认：BM25 用
  `Function(name, FunctionType.BM25, input_field_names=["text"], output_field_names=["sparse"])`
  + `schema.add_function(fn)`；sparse 字段 `SPARSE_INVERTED_INDEX` 索引 `metric_type="BM25"`。
- 官方示例用 `MilvusClient`，本任务改用等价的 ORM `CollectionSchema`/`FieldSchema`/`Collection`。

## 3. milvus-lite 是否支持 BM25 Function / sparse hybrid —— **支持**（实测结论）

关键问题结论：**milvus-lite 3.2.2 实测支持** BM25 `Function` + `SPARSE_INVERTED_INDEX` +
`hybrid_search` + `RRFRanker`，无需降级到 dense-only。端到端实测（临时 db 目录、
3 条 1024 维中文记录、dense ANN + text→sparse BM25 + `RRFRanker()`）：
`SETUP OK / INSERT OK / HYBRID OK`，Top-1 命中正确 chunk，分数降序。

唯一限制是**分词器**，不是 BM25：

- `milvus_lite/analyzer/factory.py` 源码：`tokenizer = params.get("tokenizer") or params.get("type", "standard")`，
  仅支持 `"standard"` / `"jieba"` 两种。实测传 `{"type": "chinese"}` 报
  `unknown tokenizer type: 'chinese' (supported: 'standard', 'jieba')`。
- `https://milvus.io/docs/v2.5.x/analyzer-overview.md`：`chinese` 是**完整 Milvus 服务端**
  内建 analyzer（standard/english/chinese），milvus-lite 不内置。
- milvus-lite 的 `jieba` 分词器需要安装 Python 包 `jieba`（已加入 requirements.txt）。

**因此**：brief 里的 `analyzer_params={"type": "chinese"}` 仅完整服务端可用；为让同一套
schema 在 milvus-lite 与完整服务端都成立，`MilvusStore` 默认 `analyzer_type="jieba"`
（`analyzer_params={"tokenizer": "jieba"}`，中文分词），需要时可用构造参数 `analyzer_type="chinese"`
切回完整服务端内建 analyzer。这是相对 brief 字面值的**唯一偏离**，且是向“更可移植”方向偏离。

## 4. milvus-lite 其它限制（来源：`https://milvus.io/docs/v2.5.x/milvus_lite.md`）

- 只支持 `FLAT` 索引类型（dense 用 FLAT+COSINE；sparse 的 `SPARSE_INVERTED_INDEX` 实测可用）。
- 只适合小规模向量检索；仅支持 `Strong` 一致性；不支持 partition 相关参数。
- `connections.connect(uri=<本地路径>)` 时会在该路径建一个**目录**（内含 LOCK/collections/…），
  不是单文件。测试用 `tmp_path` 放 db 目录并 `close()` 断开连接释放锁，自动清理。

## 实现映射（app/rag/milvus_store.py）

| 接口 | 底层调用 |
|---|---|
| `ensure_collection()` | `connections.connect(alias, uri)` → 不存在则建 `CollectionSchema`(id INT64 PK / text VARCHAR enable_analyzer / dense FLOAT_VECTOR dim=1024 / sparse SPARSE_FLOAT_VECTOR / category·section_path·content_type VARCHAR) → `add_function(Function(FunctionType.BM25, text→sparse_vector))` → `create_index`(dense FLAT+COSINE, sparse SPARSE_INVERTED_INDEX+BM25) → `load()` |
| `upsert(records)` | `record["dense"]→dense_vector`、`record["id"]→id`；`section_path`/`content_type` 为 None 时存空串（字段也声明 `nullable=True`）→ `Collection.upsert(rows)` + `flush()` |
| `hybrid_search(dense_vec, query_text, top_k)` | `AnnSearchRequest(dense, anns_field="dense_vector", limit=50)` + `AnnSearchRequest([query_text], anns_field="sparse_vector", limit=50)` → `Collection.hybrid_search(reqs=[...], rerank=RRFRanker(), limit=top_k, output_fields=[...])` → 映射为 `{chunk_id, text, category, section_path, content_type, score}` |

## 备注

- ORM API（`Collection`/`connections`）在 pymilvus 3.0.2 触发 `PyMilvusDeprecationWarning`：
  “will be removed in PyMilvus 3.1”。当前 `>=2.5` 无上界，未来若 pip 解析到 3.1 会破坏本实现；
  建议后续由负责人决定是否 pin `pymilvus>=2.5,<3.1`，或迁移到 `MilvusClient`（`ranker=`）。
- 完整服务端才支持的内建 analyzer `chinese` 与 milvus-lite 不兼容；`jieba` 是当前两端通用的
  中文分词选择。
