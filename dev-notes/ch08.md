## mcp Python SDK 核实（Task 5/6）

**版本钉定**：`mcp==1.30.0`（`mcp>=1.0,<2` 的最新版；经 `https://pypi.org/pypi/mcp/json` 核实）。

**为何 `<2`**：mcp 2.x 将 `FastMCP` 改名 `MCPServer`（`from mcp.server.mcpserver import MCPServer`），
并多处 API 变更。计划里服务端薄封装按 1.x 的 `FastMCP` 书写，故锁 `<2`。
2.x 迁移见官方 migration guide（`mcp.server.fastmcp` 在 2.x 导入即抛 `ModuleNotFoundError`
并提示改名）。若日后升 2.x，需重写 `build_mcp_server()` 薄封装与 `make_http_transport()`。

**已装包内省结论（mcp 1.30.0，Python 3.13.9）**：
- `from mcp.server.fastmcp import FastMCP` ✅（类 `mcp.server.fastmcp.server.FastMCP`）
- `FastMCP(name: str)` ✅；`@mcp.tool()` 装饰器 ✅（`mcp.tool()(fn)` 注册成功，`_tool_manager.list_tools()` 可见）
- `.run(transport='stdio'|'sse'|'streamable-http', mount_path=None)` ✅ —— **默认 stdio**；
  计划里 `build_mcp_server().run()` 为 stdio 薄封装。若按 spec §4.4 以 Streamable HTTP 独立进程部署，
  服务端改为 `build_mcp_server().run(transport="streamable-http")`。
- 客户端（Task 6 `make_http_transport` 用）：`from mcp.client.streamable_http import streamable_http_client` ✅
  签名 `(url: str, *, http_client=None, terminate_on_close=True) -> AsyncGenerator[TransportStreams, None]`。

**测试边界**：`tests/test_mcp_servers.py` 只测纯函数（`*_fn`），不 `import mcp`；薄封装与传输为部署/接线层，
留待环境就绪（Docker/MySQL 常驻）后真实起进程验证。
